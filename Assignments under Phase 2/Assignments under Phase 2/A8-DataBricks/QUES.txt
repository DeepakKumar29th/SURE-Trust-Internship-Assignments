Project: Marketplace Lakehouse Pipeline, Revenue Audit, and Seller Performance Intelligence
Dataset

Use the **Brazilian E-Commerce Public Dataset by Olist**.

Dataset link:
https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce

This dataset contains multiple CSV files related to real e-commerce marketplace orders, customers, sellers, products, payments, reviews, and delivery timelines.
Business Scenario

You are working as a Data Analyst / Junior Data Engineer for an e-commerce marketplace.

The company currently receives raw CSV files from different systems:

* order system
* payment system
* seller system
* customer system
* product catalog system
* review system
* delivery tracking system

The leadership team does not want a simple notebook analysis.

They want a **Databricks-based lakehouse workflow** that can take raw files, validate them, clean them, join them, create business-ready tables, and prepare outputs that can be used by dashboards.

The company is also worried about future production problems:

* new files may arrive daily
* some records may be updated later
* schema may change
* sellers may have poor delivery performance
* reviews may arrive after delivery
* dashboards may accidentally use raw data
* wrong transformations may need rollback or audit

Your task is to design and build a Databricks project that handles this like a real company workflow.

Main Business Question
Can the company build a reliable Databricks reporting layer that identifies revenue performance, seller performance, delivery problems, customer satisfaction issues, and data quality risks from raw marketplace

Bronze Layer

Raw data loaded from CSV files.

Expected idea:

* keep source data close to original form
* include ingestion metadata if possible
* preserve raw files or raw tables
* do not directly use Bronze for business dashboards

Silver Layer

Cleaned and joined data.

Expected idea:

* clean dates and timestamps
* validate keys
* handle nulls
* remove or flag duplicates
* standardize categories
* join orders, payments, items, products, customers, sellers, and reviews
* create business metrics
* separate valid records from risky records

Gold Layer

Business-ready summary tables.

Expected idea:

* seller performance summary
* category revenue summary
* state/city revenue summary
* delivery delay summary
* review score summary
* payment behavior summary
* executive KPI table

Out-of-Syllabus Databricks Concepts To Explore

You are expected to research and apply as many of the following as possible.

Do not wait for the trainer to teach these fully.

Use Databricks documentation, YouTube, ChatGPT, or other learning sources.

1. Delta Tables

Use Delta tables for Bronze, Silver, and Gold layers wherever possible.

Show why Delta tables are better than raw CSV files for reporting.

2. MERGE / Upsert

Simulate a late-arriving update.

Example business situation:

A few orders that were originally marked as delivered are later updated as cancelled or returned.

Create a small correction/update dataset and apply it to a Delta table using an upsert-style approach.

3. Schema Evolution

Simulate a new incoming file with an extra column.

Example:

A new column like `delivery_partner`, `seller_tier`, or `campaign_id` appears in a future batch.

Show how your pipeline handles or rejects this schema change.

4. Auto Loader or Incremental Ingestion

If your Databricks environment supports it, explore Auto Loader or a similar incremental file ingestion method.

If not supported, explain the limitation and create a batch-based alternative.

5. Time Travel / Table History

Show how table history can help audit changes.

Simulate a wrong update or overwrite and explain how the business can trace what changed.

6. Data Quality Quarantine

Do not only remove invalid records.

Create a separate rejected/quarantine output for records that fail business rules.

Examples:

* missing order id
* impossible delivery date
* payment value mismatch
* missing seller id
* missing review score
* negative or suspicious price/freight values

7. Performance Thinking

Explore at least one performance-related idea.

Examples:

* partitioning
* caching
* `EXPLAIN`
* `OPTIMIZE`
* avoiding unnecessary actions
* reducing repeated reads
* selecting only required columns

8. Workflow / Job Design

Create or design a Databricks Workflow / Job with multiple tasks.

Expected logical flow:

1. Ingest raw files
2. Create Bronze tables
3. Create Silver cleaned tables
4. Create Gold summary tables
5. Run validation checks
6. Produce final business report

If your environment does not allow job creation, document how the job would be structured.

9. Unity Catalog / Volumes Thinking

Use governed storage if available.

If you use volumes, document where raw files are stored and why governed storage is better than random file paths.
