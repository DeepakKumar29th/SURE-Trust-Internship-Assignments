POWER BI DAY 1 HANDS-ON PRACTICE
Topic: Building a Company-Style Executive Sales Report

Objective:
In this practice, we will build the first version of a professional Power BI report using an Excel sales dataset.

By the end of this practice, you should have:
1. A cleaned sales table named FactSales
2. A proper Date table named DimDate
3. A relationship between FactSales and DimDate
4. Business DAX measures
5. One executive summary report page
6. KPI cards, trend chart, country chart, product chart, segment matrix, and slicers

3. If the file is already loaded, stay on the main Power BI report screen.

4. Save the Power BI file first.

5. Click File.

4. A new window will open.

Power Query Editor is where we check and prepare the data before creating reports.

------------------------------------------------------------

1. In Power Query Editor, look at the left side.

2. You will see the loaded Excel sheet/table.

3. It may be named financials, Sheet1, or something similar.

4. Right-click that table name.

5. Click Rename.

6. Rename the table as:

7. Press Enter.

Reason:
This table contains measurable business data such as sales, profit, units, cost, discounts, country, product, and date. So we name it FactSales.

PART 7: TURN OFF AUTO DATE/TIME
------------------------------------------------------------

------------------------------------------------------------
PART 8: CREATE A DATE TABLE
------------------------------------------------------------

1. Go to the top ribbon.

2. Click Modeling.

3. Click New table.

4. A formula bar will appear.

5. Paste the following DAX code:

DimDate =
VAR MinDate = MIN(FactSales[Date])
VAR MaxDate = MAX(FactSales[Date])
RETURN
ADDCOLUMNS(
    CALENDAR(MinDate, MaxDate),
    "Year", YEAR([Date]),
    "Month Number", MONTH([Date]),
    "Month Name", FORMAT([Date], "MMM"),
    "Year Month", FORMAT([Date], "YYYY-MMM"),
    "Year Month Number", YEAR([Date]) * 100 + MONTH([Date]),
    "Quarter", "Q" & FORMAT([Date], "Q")
)

6. Press Enter.

7. A new table named DimDate will be created.

Reason:
DimDate will be used for time-based analysis such as sales by month, profit by quarter, and yearly trends.

------------------------------------------------------------

They should not be sorted alphabetically.

------------------------------------------------------------

2. Go to the top ribbon.

5. Select Year Month Number.

Reason:
Year Month should follow proper time order, not alphabetical order.


------------------------------------------------------------
PART 11: MARK DIMDATE AS DATE TABLE
------------------------------------------------------------

1. In the Fields pane, right-click DimDate.

2. Click Mark as date table.

3. Click Mark as date table again.

4. Select the Date column.

5. Click OK.

Reason:
This tells Power BI that DimDate is the official calendar table for this report.


------------------------------------------------------------
PART 12: CREATE RELATIONSHIP BETWEEN DIMDATE AND FACTSALES
------------------------------------------------------------

1. On the left side of Power BI Desktop, click Model view.

2. Model view looks like connected tables or boxes.

3. You should see two tables:
   - FactSales
   - DimDate

4. Find the Date column inside DimDate.

5. Drag DimDate[Date].

6. Drop it on FactSales[Date].

7. Power BI will create a relationship.

8. Double-click the relationship line.

9. Check the settings:

   Cardinality: One to many
   Cross filter direction: Single
   Make this relationship active: Yes

10. Click OK.

Expected meaning:
DimDate should filter FactSales.

DimDate is the one side because each date appears once in DimDate.
FactSales is the many side because many sales records can happen on the same date.


------------------------------------------------------------
PART 13: HIDE CONFUSING DATE COLUMNS FROM FACTSALES
------------------------------------------------------------

1. In the Fields pane, expand FactSales.

2. Right-click FactSales[Date].

3. Click Hide in report view.

4. Also hide the following columns from FactSales:

   - Month Number
   - Month Name
   - Year

Reason:
For time-based reporting, we want users to use date fields from DimDate, not from FactSales.

------------------------------------------------------------
PART 15: CREATE BUSINESS DAX MEASURES
------------------------------------------------------------

1. Click the _Measures table.

2. Go to the top ribbon.

3. Click Table tools.

4. Click New measure.

Create the following measures one by one.


Measure 1:

Total Sales = SUM(FactSales[Sales])


Measure 2:

Total Profit = SUM(FactSales[Profit])


Measure 3:

Total Units = SUM(FactSales[Units Sold])


Measure 4:

Total Gross Sales = SUM(FactSales[Gross Sales])


Measure 5:

Total Discount = SUM(FactSales[Discounts])


Measure 6:

Total COGS = SUM(FactSales[COGS])


Measure 7:

Profit Margin % = DIVIDE([Total Profit], [Total Sales])


Measure 8:

Discount Rate % = DIVIDE([Total Discount], [Total Gross Sales])


Measure 9:

Average Selling Price = DIVIDE([Total Sales], [Total Units])


Measure 10:

Cost Ratio % = DIVIDE([Total COGS], [Total Sales])


Reason:
These measures represent business metrics. They are used in visuals and change dynamically based on slicers and filters.


------------------------------------------------------------
PART 16: FORMAT THE MEASURES
------------------------------------------------------------

Format each measure properly.

1. Click a measure in the Fields pane.

2. Go to Measure tools.

3. Set the format.

Use the following formatting:


Total Sales:
Currency or Decimal Number

Total Profit:
Currency or Decimal Number

Total Units:
Whole Number

Total Gross Sales:
Currency or Decimal Number

Total Discount:
Currency or Decimal Number

Total COGS:
Currency or Decimal Number

Profit Margin %:
Percentage

Discount Rate %:
Percentage

Average Selling Price:
Currency or Decimal Number

Cost Ratio %:
Percentage


For percentage measures:
Set decimal places to 2.

For large money values:
Set display units to Auto or Millions.

END OF DAY 1 POWER BI PRACTICE
------------------------------------------------------------

Main learning:
A professional Power BI report is not built by directly dragging charts.

The proper flow is:

1. Check and prepare data
2. Build a clean model
3. Create a Date table
4. Create relationships
5. Create business measures
6. Build report visuals
7. Add slicers
8. Test whether the report responds correctly

A beginner builds visuals first.
A professional builds the model first.
